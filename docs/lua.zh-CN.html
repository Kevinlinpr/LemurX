概览

LemurX是 Android 上的 Chromium，浏览器进程里内嵌了一个 Lua 5.4 解释器，跑在自己的一条顺序线程上。脚本就是应用私有目录下的 .lua 文件：没有 manifest，没有权限弹窗，脚本和浏览器之间也没有一层"扩展 API"隔着——标签、网络栈、原生 Android 界面、DevTools 协议、Chromium 自己的服务，全部通过同一张表 lemurx 来调。

三层能力，互相可以组合：

lemurx.*LemurX原生 API。标签、网络规则、HTTP、文件、存储、浏览器外壳、声明式原生 UI、原生 View 手术、输入、Intent、cookie、历史、prefs、Chrome DevTools 协议。浏览器进程
luakit 层luakit 全部 C 级 Lua 接口在 Chromium 上的重新实现：widget{} 树映射到 Android View，webview 绑定到 Tab，luakit.register_scheme、sqlite3、regex、soup、stylesheet、timer、download、ipc_channel。luakit 的 lib/、lousy/、rc.lua 原样打包、原样运行。luakit
渲染进程每个渲染进程一个 Lua 状态（luakit 的 web extension 模型）：基于主世界 V8 句柄的 page、dom_document、dom_element；每个子资源请求上的同步 send-request 钩子；luakit.register_function 把 Lua 函数暴露给网页 JS；ipc_channel 回到浏览器进程。渲染进程

本页徽标的含义：

browser 在浏览器进程运行 · renderer 在渲染进程运行 · luakit luakit 兼容接口 · UGC ok 沙箱化的分享脚本也能用 · 仅本地 UGC 脚本调用会抛 Lua error · signal 用 add_signal 订阅的事件。

该用哪一层？ 先用 lemurx.*——它最小、最贴合 Android。需要 luakit 的对象模型（信号、property:: 通知）、 控件树、自定义 URL scheme，或者在移植 luakit 模块时，用 luakit 层。需要在页面内部同步做决定时——逐请求改写、首帧前 DOM 手术、把原生函数暴露给网页脚本——用渲染进程层。

约定与信任域

线程模型

所有脚本跑在浏览器进程里一条顺序 Lua 线程上。绝大多数 lemurx.* 调用是同步的：需要 UI 线程的操作会投递过去并等待。 回调（事件、点击、定时器、HTTP 结果）都在 Lua 线程送达，不存在并发问题。UI 线程从不阻塞等 Lua：Lua 忙时需要返回值的 Java 回调会被直接拒绝而不是等待。 唯一的例外是 luakit 控件的 key-press 裁决——UI 线程会等这个结果，等待期间协作式地执行 Lua 排队的控件操作。

  • 不要忙等（while os.time() < t），用 lemurx.timer.after / every。
  • 同步 lemurx.http.fetch 最多阻塞 Lua 线程 20 秒（UGC）/ 120 秒（本地）——所有脚本的回调都排在它后面。用回调形式或 lemurx.async。
  • tabs.eval、cdp.send、ui.* 同步但很快（等的是 UI 或渲染进程，几十毫秒）。

返回值

  • 查询类返回 table：{ok=true, ...} 或 {ok=false, error="原因"}。
  • 动作类返回 boolean。
  • "找不到"返回 nil，不抛异常。
  • 参数类型错误、UGC 调特权接口会抛错。拿不准就 pcall。

本地 vs UGC

你自己设备上的脚本不设限。限制只落在"别人写的、你装进来的"脚本（UGC，files/lua/ugc/）上。

UGC 脚本禁用：lemurx.cookie history downloads perm cdp v8 dom ax blink prefs data page network emulation overlay css、 net.addRule 的 requestBody/replaceRequestBody、任意 intent action、以及整个 luakit 层。 特权是运行时按状态判的，不看源码——UGC 里动态拼出来的代码仍是 UGC。

为什么要独立状态？ 共享状态下，一个 UGC 文件只要覆盖 lemurx.tabs.eval，等你的回调下次调到它，就在你的特权下跑了它的代码（confused deputy）。 独立状态让这一类攻击整体消失，本地脚本因此不需要做任何防御。为什么 load 只收文本？ Lua VM 不校验字节码，精心构造的字节码等于在浏览器进程里任意读写内存。

本地脚本用 lemurx.expose 显式把能力交给 UGC；UGC 用 lemurx.import 取。值按 JSON 过界，函数永远过不去。

事件

两套事件风格并存。lemurx.* 用 module.on(name, fn)；luakit 层用对象协议 obj:add_signal(name, fn)（见 对象协议）。两者都在 Lua 线程送达。

lemurx.* 事件
-- 标签生命周期。ev = {id, url, title, incognito, loading, canGoBack, canGoForward, muted, event, eventUrl}
lemurx.tabs.on("started" | "document" | "loaded" | "created" | "closed" | "selected", function(ev) end)
--  started  = 开始导航        document = DOM 可用（注入的最佳时机）
--  loaded   = 加载完成        created / closed / selected = 标签栏变化

-- 外壳事件
lemurx.chrome.on("omnibox", function(ev) end)   -- {focus=true|false, text}
lemurx.chrome.on("back",    function(ev) end)   -- {id, url, title}
lemurx.chrome.on("menu",    function(ev) end)   -- {id, title, lua}

-- 返回键。注册后返回键归你；想放行就调 lemurx.chrome.back()
lemurx.input.onBack(function(ev) end)
lemurx.input.interceptBack(false)               -- 交还系统

-- DevTools 事件（仅本地）
lemurx.cdp.on("Network.responseReceived" | "*", function(ev) end)  -- {method, tab, params}

-- 定时器（毫秒，最小 10）
local id = lemurx.timer.every(60000, function() end)
lemurx.timer.after(2000, function() end)
lemurx.timer.cancel(id)
luakit 风格信号
local webview = require("webview")
webview.add_signal("init", function(view)                 -- 每个 webview，含原生开的标签
    view:add_signal("navigation-request", function(v, uri, reason)
        if uri:find("ads%.example") then return false end -- 否决：这次导航根本不会发生
    end)
    view:add_signal("property::title", function(v) msg.info("标题变为 %s", v.title) end)
end)

luakit 兼容

luakit 是整个界面都用 Lua 写的 WebKitGTK 浏览器。LemurX把 luakit 暴露给 Lua 的每一个 C 级接口——全局表、对象协议、全部控件类型、webview、自定义 scheme、web extension（渲染进程）侧——在 Chromium 和 Android 上重新实现了一遍。 luakit 自己的纯 Lua 层（lib/、lib/lousy/、config/rc.lua、config/theme.lua）逐字节打包，正常 require。 也就是说 require("webview")、require("window")、chrome.add(...)、modes、binds、adblock、follow、formfiller、userscripts…全都能用。

开启 luakit 外壳

内核总是加载（所以 widget{}、sqlite3{}、luakit.register_scheme 对你的脚本随时可用）。rc.lua 是否运行——它会把整个外壳交给 luakit 的 window.lua：notebook、标签条、状态栏、vi 式模式——由一个开关决定：

切换 rc.lua
lemurx.storage.set("luakit_rc", "1")        -- 启动时运行 config/rc.lua（luakit 外壳）
lemurx.storage.set("luakit_autowrap", "1")  -- 把每个原生 Tab 包成 luakit webview（默认开）
-- 像在桌面一样编辑 files/luakit/config/rc.lua 和 theme.lua

刻意的差异

  • 像素按 dp，字号按 sp。 Pango 字体串（"monospace bold 12"）和 label 里的 Pango markup 会被翻译。
  • webview 就是 Tab。 widget{type="webview"} 创建一个真实的 Chromium Tab；把它放进 notebook/box，Tab 内容就挪进该控件的矩形。notebook:switch() 会选中原生 Tab，反之亦然。
  • navigation-request 是 NavigationThrottle。 返回 false 在提交前取消：不闪白、不进历史。
  • 自定义 scheme 同时服务导航和子资源；没人 finish 的请求 30 秒后超时而非永久挂起；完全没有处理器的 scheme 立刻返回 404。
  • regex 是 RE2，不是 PCRE：没有反向引用和后行断言。
  • luakit.spawn 真的起进程（/system/bin/sh 可用）；unique.is_running() 永远 false（一个包一个进程）。
  • web 模块摸不到文件系统（Chromium 渲染进程沙箱）：渲染进程里的 lfs 是行为一致的空实现。
  • Lua 是 5.4；兼容层为 luakit 5.1 时代的 lib/ 补了 unpack、loadstring、setfenv/getfenv、table.getn/maxn、math.pow、string.gfind、package.loaders。
许可。 luakit 的 lib/ 和 lousy/ 是 GPLv3，作为独立 Lua 文件连同许可证一起分发。LemurX的内核（kernel/*.lua、C++ 与 Java 宿主）是依据 luakit 文档独立实现的，不派生于 luakit 的 C 源码。

渲染进程里的 Lua

每个渲染进程都有自己的 Lua 状态，相当于 luakit 的 web extension。由浏览器侧 require_web_module("name") 加载；模块源码先在 files/luakit/config/、再在 files/luakit/lib/ 解析，经 Mojo 下发。 模块里能看到 luakit、page、dom_document、dom_element、ipc_channel、msg、soup 和安全的标准库。

它和 content script 的区别：

  • 真 DOM 句柄，主世界。 dom_element 包着一个 V8 节点句柄。同一节点永远是同一个 Lua 对象（可做表键、可用 == 比较）。读写都是同步的。
  • 不是 script 标签。 页面 CSP 管不到；页面也看不见、干扰不了 Lua 状态。
  • 同步请求钩子。 page 的 send-request 信号在每个子资源离开进程前触发——返回字符串重定向、false 拦截、就地改 headers 表。底层是 URLLoaderThrottle。
  • 把原生函数挂到 window。 luakit.register_function(uri_pattern, name, fn) 让 window[name](...) 返回一个由 Lua resolve 的 Promise。
  • 双向 IPC。 ipc_channel 双向发信号，可以定向到某个页面，也可以广播到所有渲染进程。
files/luakit/config/probe_wm.lua（渲染进程侧）
local ui = ipc_channel("probe_wm")

luakit.add_signal("page-created", function(page)
    page:add_signal("send-request", function(p, uri, headers)
        if uri:find("doubleclick%.net") then return false end        -- 拦截
        headers["DNT"] = "1"                                            -- 改请求头
        if uri:sub(1, 7) == "http://" then return "https://" .. uri:sub(8) end  -- 重定向
    end)
    page:add_signal("document-loaded", function(p)
        for _, a in ipairs(p.document.body:query("a[target=_blank]")) do a.attr.target = "_self" end
        ui:emit_signal("links_fixed", p.id, #p.document.body:query("a"))
    end)
end)

luakit.register_function("^https?://", "lemurPing", function(page, resolve, reject, msg)
    resolve("pong: " .. tostring(msg))    -- 网页 JS：await lemurPing("hi")
end)
files/lua/20_probe.lua（浏览器侧）
local wm = require_web_module("probe_wm")

    lemurx.toast(("标签 %d：%d 个链接"):format(page_id, n))

坑与限制

  • net.addRule 与子资源。 浏览器侧规则作用于导航（document / sub_frame）和浏览器发起的请求。要逐请求控制页面子资源，用渲染进程的 send-request 信号，它能看到每个 img/script/xhr/fetch。
  • 对当前标签 tabs.hide 会让屏幕空白——先 select 别的标签。
  • theme.set({dark=...}) 走LemurX自己的暗色切换，带应用重启标记；别频繁切。
  • toolbar.* 挂载点宽 150 dp——放一个按钮，最多两个。
  • page.top / page.bottom 是 PopupWindow，横竖屏切换时重建；ui.update 比重新 render 便宜得多。
  • UI 调用是阻塞的。 一次回调里别 ui.find 四十次——dump 一次自己在 Lua 里筛。
  • eval 只返回可 JSON 序列化的值。 DOM 节点会变成 nil；要节点就用渲染进程层。
  • 加载顺序 = 文件名顺序。 跨脚本全局变量要注意数字前缀；更稳的做法是共享代码放 files/lua/lib/，用 require。
  • 本地脚本拥有完整的 os 和 io。 os.exit() 直接杀掉浏览器进程；io.open 能读写应用私有目录任何文件。这是刻意给的自由——别教新手乱用。
  • UGC 脚本之间也互相隔离。 通过 lemurx.storage 或本地桥脚本通信。
  • 桥只传数据，不传函数。 import 到的函数不能收 Lua 回调；改成轮询 storage 或订阅事件。
  • luakit init 时序。 webview.add_signal("init") 只对注册之后创建的 webview 触发。对已存在的标签，遍历 lemurx.tabs.list() 并调 __lk.webview_for_tab(id[, true])（LemurX辅助函数）补挂或包装，案例脚本就是这么做的。
  • scheme 请求必须回应。 挂了处理器却始终不调 request:finish，导航 30 秒后失败。
